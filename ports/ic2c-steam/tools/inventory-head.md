# Legal inventory of the IC2C profile (facts for the publishing decision)

Profile: `ports/ic2c-steam/`. Generated by `tools/inventory.sh` =
`porter inventory` (the tables below and every number in them; the method is the same token 8-gram overlap as the
first inventory). This is a factual inventory, not legal advice. "IC2C" = IC2 Classic (2.1.3.4 for Minecraft 1.19.2,
1.2.6 for 1.7.10), all rights reserved by its authors; the profile must not contain IC2C's code, textures or texts, nor
code adapted from them.

## What the profile does NOT contain
- No IC2C jar, class, decompiled source, texture or lang file. Everything derived from IC2C (decompiled sources, the
  IR, converted textures and lang, the rewritten closure of the steam AND the barrel/drink/refinery logic, the hub
  stubs, the rules from IC2C's registry fields to the generated content) is produced on the player's machine from the
  player's own two jars (sha256-checked) and stays in the player's run directory.
- No mapping files, no Minecraft code.

## How the logic is made (no adapted code shipped)
- The steam and the barrel/drink/refinery/potion logic is IC2C 2.1.3.4's own code, copied on the player's machine as a
  dependency closure of its seed classes and rewritten by porter's public rules plus the profile's rules (`rules/`).
- Hub classes the closure stops at (registries, networking, rendering) are generated stubs (`porter stubs`); the few hub
  members that need a 1.7.10 value get it from declaration rules (`rules/port-ic2c/hubs.rule.yaml`, `install.stubs.keep`)
  or from hand-written 1.7.10 adapters (`overlays/adapters/.../compat`).
- The generated content constructs the ported classes with IC2C's own constructor arguments (extracted from the
  player's decompile); the rules from IC2C's registry holder fields to the generated content are generated too.

## Categories
- **A** configuration, rules and data that reference IC2C names (interoperability facts): the port config, `select/`
  (unit specs, logic class lists, IR overlays with recipe facts), `rules/`, `edits/` (decompiler artefacts),
  `scenarios/`. Rule tests are synthetic code (only owner names are IC2C's).
- **B** hand-written code: the extractor pattern pack, the 1.7.10 adapters bridging to IC2C 1.2.6's public API
  (`overlays/adapters/.../compat`), the addon's own project files (mod class, wiring, phase-1 reactor/turbine port,
  guide book, build files, lang). Highest overlaps are host-API idioms (`ReactorHelper`, `GuiHandler`: ForgeDirection
  loops and IGuiHandler shapes of the IC2C 1.2.6 code they call), not adapted logic.
- **C** adapted from IC2C, shipped: what is left of the blind patches and the texture pixel overlay.
- **D** docs, launcher, the inventory tool.
