# porter v0.1.0

porter ports Minecraft Forge mods between versions. v0.1.0 is the first public release: the Forge 1.19.2 → Forge
1.7.10 pair, end to end, as **one CLI** driven by one config file per port.

## Highlights

- **`porter port --config <mod>.port.yaml`** runs a whole port: generate → closure → rewrite → install → loop →
  compile → build → test. Progress is saved; a re-run resumes at the first unfinished stage. Every run writes
  `port-report.md` with metrics and an explicit list of what was **not** ported and why.
- **The closure algorithm**: unknown classes are copied recursively; classes known on the target side with an
  identical API are left alone; everything else that differs becomes compile errors that are resolved **once per
  distinct symbol**. Hubs (registries, networking, ...) are cut and replaced by stubs of exactly the members the
  closure uses.
- **Two modes**: `full` (port a mod that does not exist on the target version) and `delta` (an addon over an
  existing older version).
- **Reuse metric**: `porter coverage` reports, before any AI work, how much of a mod's distinct API the existing
  rules already resolve.
- **Rules and adapters from two real ports**: 513 public adapter rules (opt-in pack `rules/packs/adapters`: 374 from
  the reference closure port, 139 modern-API rules from the TorchMaster demo) and a 125-class 1.19.2-API adapter pack (block
  states, block entities, menus/screens, capabilities, fluids, NBT, mod lifecycle, configs, deferred registers, entity
  types, commands, ...), each rule with before/after tests; 767 curated rules in total for 1.19.2 → 1.7.10, plus ~9,200 mechanical rules
  generated from the local symbol graph.
- **NotEnoughItems integration** for generated 1.7.10 content (recipe types, custom recipes, multiblock structures;
  on by default, `--no-nei` to skip); IR schemaVersion 2 (RFC 003).
- **GUI checks** in testkit (RFC 005): GUI captures on 1.19.2 and 1.7.10 clients, structural and image comparison,
  HTML/Markdown report.
- **Rule language** (RFC 006): statement and expression `pattern` rules with placeholders, declaration edits
  (supertypes, members, initializers, method bodies, removals), position and type preconditions (`extends`
  position, receiver type), `$target(...)`. 23 of the 43 counted edits of the reference closure port became rules.
- **Short console output by default**: every command prints a summary of at most about 20 lines (success, or the
  failure grouped by cause) and the path of the full log under the reports/work dir; `--verbose` prints everything.
  `porter port` prints one line per stage (stage, status, duration, key metric). The JSON reports are unchanged.
- **Batched scenarios**: `porter test run|diff` with several server scenarios of one version and mod set run them in
  ONE Minecraft launch per version (the world is reset between scenarios; `--no-batch` restores one launch each).
- Commands: `port`, `closure`, `coverage`, `stubs`, `passes`, `castfix`, `symbols`, `obfcheck`, `drafts`,
  `extract`, `generate`, `assets`, `rewrite`, `loop`, `graph build|query`, `test run|diff|roundtrip`, `validate`.

## Validation

porter was validated on a private port of a large tech mod (not open-licence; nothing of it is in the repository):
a 1.19.2 subsystem with its dependency closure, ported into a 1.7.10 addon (`mode: delta`).

| | |
|---|---|
| closure | 281 classes / 28k lines + 45 hubs (28 generated stubs, 17 hand-written) |
| first pass | 10,533 automatic rewrites, 3,167 javac errors over 610 distinct symbols |
| resolution | 14 rounds, 610 → 0 distinct symbols; 374 of the resulting rules are generic and public |
| scenarios | equal to the 1.19.2 original tick for tick (363/363, 402/402, 402/402 samples) |
| coverage | 733 distinct API symbols: 34.2% resolved by the core rules + symbol graph, 58.9% with the adapter pack |
| reproducibility | the whole port expressed as one `*.port.yaml`; `porter port --restart` on a clean checkout rebuilt the same jar byte for byte (generate, closure, rewrite, install, loop, compile, build; 0 javac errors, 0 reobf collisions) |

## Requirements

JDK 21 for porter; JDK 17 for 1.19.2 mods; JDK 8 toolchain (+ JDK 17–25 for Gradle) for 1.7.10 mods
(RetroFuturaGradle); NotEnoughItems 1.0.5.x + CodeChickenCore + CodeChickenLib as `compileOnly` in the target project
for the generated NEI integration (or `--no-nei`). Linux, macOS and Windows (Git Bash for the helper scripts).

## Install

Download `porter-0.1.0.zip` from the release, unzip, add `bin/` to `PATH` (`bin/porter`, `bin/porter.bat`). The zip
contains the jars, the public rule packs (`rules/`), the contract schemas and examples, and the docs. See the README
quickstart.

## Known limitations

- One version pair; `porter report` is planned.
- The adapter pack compiles only with a 1.7.10 MCP jar (`-Pporter.mc1710Jar`).
- Some recipe shapes have no IR concept yet (e.g. fluids in a crafting grid); they are listed in the port report.

## Open-licence demo: TorchMaster (MIT)

A second, fully public port: [TorchMaster](https://github.com/Xalcon/TorchMaster) 19.2.93 (MIT, xalcon: Mega Torch,
Dread Lamp, Feral Flare Lantern, Frozen Pearl) from Forge 1.19.2 to Forge 1.7.10, where the mod does not exist
(`mode: full`). The profile is `ports/torchmaster/` (config, six differential scenarios, README; the mod's code is
not in the repository: you run it against your own copy of the original), listed in `ports/catalog.yaml`.

| | |
|---|---|
| ported | all 28 classes as a standalone 1.7.10 mod; 0 javac errors, the RFG build passes, reobf check clean |
| scenarios | 6 scenarios, **67/67 samples equal** between the 1.19.2 original and the 1.7.10 port |
| time | a from-scratch `porter port` in **4 min 51 s** (generate, closure, rewrite, install, compile, build, tests) |
| resolution | 113 → 0 distinct symbols in 4 rounds (113 → 17 → 7 → 4 → 0) |
| rule reuse | 56% of the applied rules existed before this port (126 of 224 distinct), 66% by occurrence (535 of 811 rewrites) |
| manual edits | **0** call-site edits (one 45-line `@Mod` entry point is the only hand-written class) |
| left behind | 139 generic modern-API rules and 44 adapter classes, all with tests, now in the public packs |

Known gaps (also in the port report): village sieges cannot be blocked because 1.7.10 Forge has no siege event
(the subscriber compiles against an adapter event that is never posted); the multi-element JSON models (Dread Lamp,
lantern) are not converted, so those blocks render with the 1.7.10 block renderer and the Dread Lamp has no 1.7.10
texture; the result is not yet checked in a real client.
