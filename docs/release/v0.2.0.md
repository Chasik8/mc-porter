# porter 0.2.0

## Highlights

- **`porter run <port-dir>`**: one command for a ready port. It checks the original jars you downloaded (sha256),
  sets everything up (JDKs, Forge, mappings, symbol graph) and builds the ported mod. `run.bat` / `run.sh` in every
  `ports/<mod>/` folder; tested on Windows and Linux (byte-identical jars).
- **`ports/` layout and catalog**, with guides: use a ready port, port your own mod, share a port back.
- **IC2 Classic steam and barrels for 1.7.10** (`ports/ic2c-steam/`): rebuilds the 1.19.2 steam reactor GUI, steam
  turbines, fuel boiler, steam tunnel, barrels (beer, rum, whisky), refinery, guide book and NEI pages as an addon for
  IC2 Classic 1.2.6, from your own copies of both IC2 Classic jars. The profile contains no IC2 Classic code or assets.
  Verified: 6 differential scenarios equal tick for tick against IC2 Classic 1.19.2, plus refinery and turbine runs.
  First run about 15 minutes, re-run about 4.
- **Profiles that ship nothing of the original** (RFC 009): `setup`/`derive` steps, blind patches, `porter decompile`,
  `porter select`, `porter inventory` (overlap with the original's sources).
- **Rule language** (RFC 006 patterns and declaration edits) and many new rule/adapter packs (food and effects, fluid
  tanks, modern registries, entity helpers); a CFR lambda pass; generated hub stubs.
- **CI for ports**: every PR that touches `ports/<mod>/` builds and tests that port on a clean runner (open-licence
  ports; closed-licence ones are verified by maintainers locally); nightly regression of all ports; one CI run per
  hour per contributor.
- **Faster tests**: both Minecraft versions run at the same time; independent scenarios run simultaneously in one
  world with a per-scenario failure list; compact console output.
